classification for this declared inventory. It does not claim full Gust
language parity, identical machine code, identical emitted C, or identical
backend-specific diagnostic prose.

## Entry schema

Every `parity_entry` line contains:

- `id`
- `family`
- `source_fixture`
- `mir_fixture`
- `deferred_fixture`
- `deferred_family`
- `canonical_mir_operations`
- `types_abis`
- `mir_registry_feature`
- `mir_to_c_guard`
- `canonical_oracle_guard`
- `translator_seed_guard`
- `source_native_guard`
- `baseline_source`
- `positive_expectation`
- `deferred_expectation`
- `route_owner`
- `migration_status`
- `ci_family`
- `seed_import`

Allowed route owners are `generic_canonical_mir` and `deferred`.
`legacy_exact_shape` is a historical value only and is prohibited from active
entries after Patch 11. All twelve supported entries enter through the generic
canonical-MIR route. Module and import support is
defined by resolver order, fully qualified symbol identity, exact signatures,
explicit `bundle_export`/`imported_bundle` linkage, and the approved host
registry rather than by the literal `abs` cohort. The host registry currently
classifies `abs(int)->int` as `RuntimeCall` and `toupper(int)->int` as
`ExternFunction`; no source can add a linker flag, library, search path, or
environment override. A `none_*` value is an explicit evidence gap or
non-applicable field, never an omitted field. Indirect calls, closures, dynamic
loading, non-scalar ABIs, and unapproved host symbols remain deferred.
