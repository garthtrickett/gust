This registry is the machine-checkable Phase 11 source of truth. It imports the
four existing MIR feature-migration entries and all seventeen frozen
MIR-to-Cranelift translator seeds, then adds the two Phase 10-only call
capabilities needed to account for the six connected source cohorts without
pretending that the translator inventory already covers them.

Registry parity means equivalent observable behavior and equivalent failure
classification for this declared inventory. It does not claim full Gust
language parity, identical machine code, identical emitted C, or identical
backend-specific diagnostic prose.

## Entry schema

Every `parity_entry` line contains:

- `id`
- `family`
- `source_fixture`
- `mir_fixture`
- `deferred_fixture`
- `deferred_family`
- `canonical_mir_operations`
- `types_abis`
- `mir_registry_feature`
- `mir_to_c_guard`
- `canonical_oracle_guard`
- `translator_seed_guard`
- `source_native_guard`
- `baseline_source`
- `positive_expectation`
- `deferred_expectation`
- `route_owner`
- `migration_status`
- `seed_import`

Allowed route owners are `legacy_exact_shape`, `generic_canonical_mir`, and
`deferred`. Patch 5 records ten generic owners. Three are ordinary-source
local-state migrations: read-after-write local access, branch-arm local updates,
and declaration/assignment provenance. Local indices are serialized in source
declaration order, and the local-state worker validator accepts a generic i32
local inventory rather than a zero-or-one-local profile. A `none_*` value is an
explicit evidence gap or non-applicable field, never an omitted field. The
multiple-locals-and-assignments deferred family is now migrated; nested CFG,
loops, broader scalar operations, calls, and module expansion remain deferred.
